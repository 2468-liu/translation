### 切段规则（可复现，不靠眼睛）

```
dense   25s 窗口内 >= 15 条字幕
        阈值试过三轮：12 条选出的只是「刚过线」的段落
                      18 条全片只剩 1 段（n=1 的召回样本没有统计意义）
                      15 条贴合本片实际密度分布（多数段落 10~15 条）
quiet   孤立短句：前空档 >= 2.5s、后空档 >= 2.5s、句长 <= 4s，以它为中心取 25s
action  25s 窗口内 1~3 条字幕 —— 至少有 1 条
        ⚠ 第一版把「0 条的纯动作段」也标成 action，那是另一种素材，
          测的是误触发不是漏识别，已拆成 silent 单独一类
silent  25s 窗口内 0 条字幕
跳过   前 40s（片头无台词）、7100s 之后（片尾 119:21 起为片尾曲）
```

重建：`python scripts/probe_cut_clips.py [--cut]`
（探针按惯例不入库；入库的是 `samples/ds2_*` 与本节文字。）

### 三点使用注意

**一、`_timing.json` 的键必须是 `segments`。** `perf_compare._segments` 只认
`segments` / `rows` / `utterances` 三个键，遇到不认识的键**返回空列表而不报错** ——
覆盖率会拿空分母算出一个看起来正常的数。这与 e2e_first_tr_to_paint 434ms 那一族同源，
所以用 `scripts/probe_check_timing_readable.py` 拿消费者自己验，而不是重写一遍读法。

**二、`silent` 段不参与召回率。** 它们没有台词，算召回没有分母。

**三、这是动作片，不是对白片。** 对白密度够用（0:10~0:50、1:00 段每 25s 有 100~133 条），
但配乐和动作掩盖多，**测 AGC 的「安静段落里突然一句轻声」不如对白片典型**。
这部当极端场景（配乐压对白）用，AGC 主素材应是生活大爆炸那类对白片。

## 时间轴文件

回放用 `TRANSLATION_SAMPLE_TIMING` 指向的文件算覆盖率，
**所以它是分母，不是参考**。

| 文件 | 段数 | 来源 | 备注 |
|---|---|---|---|
| `smoke_10s_timing.json` | 2 | 手工 | 无 `i` 字段，回放时按顺序补号 |
| `blog_3min_timing.json` | 16 | 自动（强制 en，TTS 英语无碍） | |
| `e_3min_timing.json` | 21 | 自动，分片级 | 纯英语，`lang` 全为 en |
| `er_3min_timing.json` | 42 | 自动，分片级 | 俄语 3 段已正确检出 |
| `clip222_90s_timing.json` | 33 | 自动，分片级 | ja 置信度 0.88–0.96 |
| `meeting_6min_timing.json` | 140 | 自动，分片级 | 11 语种 |

字段：`{i, start, end, lang, src, p, text}`

- `src`：`auto` = 自动检测；`manual` = 人工标注。**两者不可混在一个字段里**——
  低置信度的自动检测不是锚点，人工标注才是真相
- `p`：检测置信度

重建命令：

```bash
python scripts/build_timing.py --wav samples/X.wav --out samples/X_timing.json \
    --expect ja,en,ko          # 期望出现的语种，缺任一则拒写
```

**它会在校验失败时拒写**：编号错乱、`end<=start`、非单调、超出素材长度、
预期语种缺失、预期多语种却只出一语种。写完读回比对，不一致即报错。

## 三个已经踩过的坑

**一、不要用 RMS 阈值判断停顿。**

本文件上一版写着 `er_3min` 和 `e_3min` 都是"0 次 ≥1s 停顿"。那是用
`rms < peak × 2%` 统计出来的，**是阈值造出来的假象**：这两份素材的底噪是响处的
20.5% 和 30.6%，永远不可能掉到峰值的 2% 以下。

管线自己的埋点给出的真实情况：

```
vad.end why:  silence 83   soft_cut 6   max_length 1
vad.silence:  bin=ge1000  35 次，其中一次 ms=9568.0
```

**停顿应该由 `vad.silence` 的分箱说，不由外部阈值猜。**

**二、不要用 clip 级 `language=None` 判断多语种素材。**

`transcribe(language=None)` 只在开头检测一次，然后把这个语种强加给全片。
用它跑 `clip222_90s`，整段按英语解码，日语语音被编成**看起来通顺的英语幻觉**：

```
"How do you speak Japanese?"     ← 不是音频的内容，是英语解码器编的
"Is it strange?" / "I'm so surprised."
```

上一版的 `clip222_90s` 描述（"ja8+en+ko+zh 无序切换"）就是这么来的。

正确做法是**每段单独判语种**：先用 VAD 切出语音段（此时用固定语种只为定位），
再对每段单独解码。`build_timing.py` 就是这么做的。

**四、`ds2_*` 的参考时间轴来自电影 SRT，不是管线产物。**

上面这批 `_timing.json` 全部是 `build_timing.py` 用识别引擎自己切的，所以它们
既是分母又是被测对象的一部分——**「覆盖率」在那一刻有一部分是在拿自己量自己**。

`ds2_*` 这一批的分母来自电影自带字幕：一个 1113 条、时间覆盖 99.8% 的第三方
文本。**这是它和上面几份唯一但重要的区别**，也是它更适合当召回率基准的原因。
代价是它只覆盖有台词的地方，`silent` 段仍然只能测误触发。

**五、SRT 不能当误触发的参考答案。**

`ds2_silent_*` 段在 SRT 里是空的，但那不等于音频里没有声音——未翻译的外语台词、
歌词、画外音、笑声都不在字幕里。**「没有字幕」≠「没有台词」。**

所以三类指标分算，不能合成一个：

```
召回率    对着 SRT 的 segments 算，有分母
误触发    只看 silent 段的输出量 + 人工听最频繁的约 20 个窗口确认
延迟/体感  不需要参考
```

旧版所有 `_timing.json` 都是内联命令用 `language='en'` 强制生成的：

```
meeting_6min_timing.json   165 句，含日/韩/汉字/西里尔/阿拉伯字符的数量：0
er_3min_timing.json        26 句，含西里尔字符 0 句
                           末句 'Get to work, son. Shul shul.' ← 俄语被译成英语音译
```

会议录音有 11 种语言、俄语有 3 段，而时间轴里一段都没有。
**覆盖率是拿这个文件当分母算的，所以那些覆盖率数字当时测的是时间轴，不是管线。**
已全部重建。

## 取数纪律

- 一次只动一个变量。
- 每格跑 3 次取中位数和区间。
- 臂的身份只能来自 manifest（观测到的配置），臂名不算证据。
- 大文件零点独占时段跑，不与回放并行。
- 判废的格留在附录并写明原因。
- **素材性质先查这份文件，不靠记忆。**本文件的前两版都写错过。
